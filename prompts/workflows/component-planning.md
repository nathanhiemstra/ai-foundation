# Component Planning

I use this when planning or building UI components.

## Questions To Answer

- Should this be reusable?
- Should it be split into smaller components?
- Where does it belong in the existing component hierarchy?
- Does an existing component or helper already solve this?
- Is the API/data shape easy to understand?
- Can content authors use it safely?
- Does it fit the project's docs/component library conventions?
- Does it protect accessibility, performance, and future maintainability?

## Approach

Prefer established project patterns over inventing new ones.

Think about the full system:

- Front-end output
- Content author experience
- Data/API shape
- Reusability
- Accessibility
- Performance
- Documentation consistency
- Future maintenance
