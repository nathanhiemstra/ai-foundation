# Code Review

I use this when reviewing code.

## Approach

Lead with findings. Prioritize real risks over style preferences.

Review for:

- Bugs
- Accessibility issues
- Performance risks
- User experience problems
- Maintainability concerns
- Inconsistency with project conventions
- Missing edge cases
- Overly complex implementation
- Unclear naming or structure

## Output

- Put findings first, ordered by severity.
- Be specific about the risk and location.
- Keep summaries brief.
- If there are no meaningful issues, say so directly and mention any remaining test gap or residual risk.
